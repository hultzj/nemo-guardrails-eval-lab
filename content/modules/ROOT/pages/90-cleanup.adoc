= Cleanup
:navtitle: Cleanup

== Remove what you created

You created a `NemoGuardrails` resource and five rail ConfigMaps. Look at them first, then
delete them, from your workbench terminal. The workbench, its files (the cloned lab and your
notebook results), the live monitor and your project belong to the lab and stay.

[source,bash,role="execute",subs="attributes+"]
----
NS=$(cat /var/run/secrets/kubernetes.io/serviceaccount/namespace)
oc -n $NS get nemoguardrails -o name
oc -n $NS get configmap regex-only content-safety tuned self-check self-check-edited -o name
----

Expected result: `nemoguardrails.trustyai.opendatahub.io/nemoguardrails`, and
`configmap/regex-only`, `configmap/content-safety`, `configmap/tuned`, `configmap/self-check`,
`configmap/self-check-edited`
(a configuration from a module you skipped is reported `NotFound`).

[CAUTION]
====
The next block deletes them. Your workbench keeps running: the lab owns it.
====

[source,bash,role="execute"]
----
oc -n $NS delete nemoguardrails nemoguardrails --ignore-not-found --wait=true
oc -n $NS delete configmap regex-only content-safety tuned self-check self-check-edited --ignore-not-found
oc -n $NS get deploy,route -o name
----

Expected result: one `deleted` line for each resource you created (`nemoguardrails`,
`regex-only`, `content-safety`, `tuned`, and from Module 5 `self-check` and `self-check-edited`), and the last command lists only `deployment.apps/rails-monitor` and
`route.route.openshift.io/rails-monitor`: the operator removed the guardrails Deployment, Service
and Route with the resource. (The workbench runs as a StatefulSet, so it is not in this list.)

== Remove the lab environment (whoever deployed it)

Only the person who ran the bootstrap removes the environment. From a cluster-admin shell in
a checkout of this repository, first look at what the teardown will delete. Every Application
listed goes, along with everything it created, including every `*{tenant_suffix}` namespace:

[source,bash,subs="attributes+"]
----
make -C automation status
oc get namespace -l app.kubernetes.io/part-of=nemo-guardrails-eval-lab
----

Then delete it and confirm the namespaces are gone:

[source,bash,subs="attributes+"]
----
make -C automation teardown
oc get namespace -l app.kubernetes.io/part-of=nemo-guardrails-eval-lab
----

The last command prints `No resources found` once deletion completes. Two things outlive the
teardown, by design or because they were created outside Argo CD:

* The Keycloak users from `make users`. Remove them in the Keycloak admin console if they are no longer needed.
* Each participant's workbench storage (a 5 GiB volume) goes with their project.
* *Earlier versions of this lab* used the console's Web Terminal, and kept its operator on teardown.
  A cluster deployed with one keeps the Web Terminal and DevWorkspace operators. If nothing else
  uses them, look first (`oc get devworkspaces -A`, `oc get subscription,csv -n openshift-operators
  | grep -E 'web-terminal|devworkspace'`), then delete any DevWorkspaces, both Subscriptions and both
  CSVs, and finally the leftovers the DevWorkspace operator documents: the `controller.devfile.io`
  validating and mutating webhook configurations first, then the `devworkspace-webhook-server`
  Deployment and `devworkspace-webhookserver` Service in `openshift-operators`, the
  `web-terminal-exec` and `web-terminal-tooling` DevWorkspaceTemplates, the four `devfile.io` CRDs,
  and the `devworkspace-*` ClusterRoles and bindings. Removing the webhook server before its webhook
  configurations would make pod operations fail cluster-wide.
