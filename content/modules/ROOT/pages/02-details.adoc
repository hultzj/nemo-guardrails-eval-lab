= Prerequisites and Environment
:navtitle: Prerequisites and Environment

== What you need

|===
| If you are… | You need

| Every participant
| A username and password from the facilitator, and a browser. Everything else runs in your
OpenShift AI workbench: a JupyterLab with a terminal for the platform steps (Modules 1 and 2, and
the configuration changes in Modules 4 and 5) and notebooks for the measurements (Modules 3 to 5).

| A presenter
| The same, plus a second browser window for the live monitor so the audience sees decisions arrive.
|===

Provided by the facilitator:

* An OpenShift {ocp_version} cluster with OpenShift AI {rhoai_version} (TrustyAI and workbenches enabled) and this lab deployed through OpenShift GitOps.
* Your own Data Science Project, `<your username>{tenant_suffix}`, with a running workbench, `guardrails-lab`, and the live monitor.
* The shared safety model in `{lab_namespace}`.

Commands in the workbench run as the *workbench's identity* (its ServiceAccount), which holds
exactly the permissions you hold in your project: read everything except Secrets; create and
change ConfigMaps and `NemoGuardrails` resources. Nothing else, and nothing outside your project.

== Open your workbench

.Video: this step on the lab cluster (waits sped up, no credentials shown)
video::lab-open-workbench.mp4[width=100%]

. Open the OpenShift AI dashboard, `https://rh-ai.{cluster_domain}`, and log in with *keycloak* and your username and password.
. In the left menu click *Projects*, then your project, *<your username>: guardrails lab*.
. Open the *Workbenches* tab. The row *guardrails-lab* shows the image *Jupyter | TrustyAI | CPU | Python 3.12*, *3.5*, *Latest*, and the status *Ready*. Click the workbench name, *guardrails-lab*: JupyterLab opens in a new browser tab.
. If OpenShift asks you to authorize access, click *Allow selected permissions*.

Expected result: a new browser tab titled *JupyterLab* at
pass:c,a,q[`https://rh-ai.{cluster_domain}/notebook/<your username>{tenant_suffix}/guardrails-lab/lab`], with the
file browser on the left.

== Get the lab files and run the pre-flight check

.Video: this step on the lab cluster (waits sped up, no credentials shown)
video::lab-preflight.mp4[width=100%]

In JupyterLab choose *File > New > Terminal*. Run the block below in that terminal: it fetches the
lab files onto your workbench's storage (they survive a workbench restart), from the repository
and revision the lab was deployed from (the `lab-source` ConfigMap in your project), and checks
what the workbench may do. Re-running it updates the files to that revision. Running a notebook
saves its outputs into the file, so git then refuses (`Your local changes ... would be overwritten`)
and changes nothing; keep your copy with `git -C ~/nemo-guardrails-eval-lab stash` and re-run.

[source,bash,role="execute",subs="attributes+"]
----
NS=$(cat /var/run/secrets/kubernetes.io/serviceaccount/namespace)
REPO=$(oc -n $NS get configmap lab-source -o jsonpath='{.data.repoUrl}')
REV=$(oc -n $NS get configmap lab-source -o jsonpath='{.data.revision}')
mkdir -p ~/nemo-guardrails-eval-lab && cd ~/nemo-guardrails-eval-lab && { [ -d .git ] || git init -q; }
git fetch -q --depth 1 "$REPO" "$REV" && git checkout -q --detach FETCH_HEAD && echo "lab files at $REV: $(git log --oneline -1)"
cd ~
oc whoami
oc get namespace $NS
for r in nemoguardrails.trustyai.opendatahub.io configmaps; do
  echo "create $r: $(oc auth can-i create $r -n $NS)"
done
echo "get pods/log: $(oc auth can-i get pods --subresource=log -n $NS)"
echo "get secrets: $(oc auth can-i get secrets -n $NS)"
echo "create in {decoy_namespace}: $(oc auth can-i create configmaps -n {decoy_namespace})"
git -C ~/nemo-guardrails-eval-lab ls-files notebooks
----

Expected result: `oc whoami` prints `system:serviceaccount:<your username>{tenant_suffix}:guardrails-lab`,
the namespace is `Active`, the two `create` lines and `get pods/log` print `yes`, `get secrets` and
the create in another tenant's project print `no`, `lab files at main: <commit> <message>` names
the fetched commit, and the last command lists `notebooks/03-evaluate.ipynb`,
`notebooks/04-tune-and-break.ipynb`, `notebooks/05-llm-judge.ipynb`, `notebooks/dataset.jsonl` and
`notebooks/labeval.py`. The `no` lines are
the point: the lab grants exactly what the exercises need.

The first line sets up a new terminal; re-run it whenever you open another terminal tab.
